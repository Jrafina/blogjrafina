# 桌宠素材说明（透明舞蹈视频）

页面左下角的桌宠由两段**带 alpha 通道的 WebM**（VP9 yuva420p）驱动，
素材放在 `assets/pet/`：

| 文件 | 来源视频 | 时长 | 尺寸 | 体积 |
|---|---|---|---|---|
| `dance-1.webm` | `d1fbf8e64c82d6472df3a75e6783e1af.mp4` | 12.04s | 480×480 | ≈1.7 MB |
| `dance-2.webm` | `30e411ffefdf44354bc14ddedfb9b933.mp4` | 12.04s | 480×480 | ≈1.6 MB |

原始视频是 720×720 / 24fps / HEVC，画面里除舞者外还有：
顶部标题「这是世界上最残忍的生物」、右上角台词气泡、右下角水印「豆包AI生成」、
以及米色渐变背景。抠像时全部剔除，只保留舞者本体（含其自带的白色描边）。

## 抠像做法

1. **主体分割**：`isnet-anime.onnx`（动漫角色专用 ISNet，1024×1024 输入，NCHW）。
   逐帧推理出 alpha，再做 min-max 归一化。
2. **时序平滑**：相邻帧 alpha 做 `0.6·当前 + 0.4·上一帧`，压住逐帧抖动。
3. **固定叠加层压制**：标题/水印这类"整段不动"的元素会被模型误判为主体。
   先按 8fps 采样算出**整段的时间静态图**（逐像素灰度极差 ≤5），
   在顶部 150 行内把静态像素的 alpha 直接清零——人在动、叠加层不动，这条判据很稳。
4. **连通域过滤**：在 1/4 分辨率上做连通域标记，丢掉面积过小的孤立块。
5. **收边 + 羽化**：3×3 最小值滤波收 1px（去掉背景色描边光晕）→ 3×3 均值模糊羽化 →
   再做一次 `(a-0.02)/0.96` 的对比度拉伸。
6. **统一取景**：两段视频共用同一裁切框（裁掉 y<108 的标题带，正方形 594×594），
   缩放 lanczos 到 480×480，`libvpx-vp9 -crf 38 -pix_fmt yuva420p -auto-alt-ref 0` 编码。

> 注意：`yuva420p` 的 alpha 只有用 **libvpx-vp9 解码器**才能读出来。
> 用 ffmpeg 自带的原生 vp9 解码器解出来全是 255（看着像"没有透明"），别被这一点误导：
> `ffmpeg -c:v libvpx-vp9 -i dance-1.webm -frames:v 1 -pix_fmt rgba out.png`。

## 切换实现

见 `js/deskpet.js`：两个 `<video muted playsinline>` 叠放，同一时刻只有一个 `is-active`；
每段 `ended` 后把另一段 `currentTime` 归零并播放，靠 CSS `opacity` 交叉淡入淡出。
另有一个按 `duration` 计算的兜底定时器，防止个别浏览器不触发 `ended` 时桌宠定格。

## 已知取舍

- 头顶那根呆毛（细节）顶部约 5px 随标题带一起被裁掉——它紧挨标题、且常被模型判为叠加层。
- 脚底原有的柔和投影被保留（算角色自体的一部分）；CSS 里另加了 `drop-shadow` 增强分离。
- 首次加载需要下载约 3.3MB 视频，`preload="auto"`；移动端按视口缩小到 116–148px。

## 部署注意

服务器需给 `.webm` 返回 `Content-Type: video/webm`
（nginx 默认 mime.types 已包含；若被当成 `application/octet-stream`，
部分浏览器会拒绝播放，表现为桌宠不出现）。
